# 小红书团餐实拍图文

用一组真实照片讲清一件事。读者能从图里看出员工吃什么、盒饭怎么装，或后厨到底长什么样。让业务从照片的来处或用途里自然出现。

## 工作方式

1. 先确认本次交付。只有文案改稿时读现有图序和文案，按原页序写。只有排版任务时优先用现有正文理解主题。制作完整图集时，从用户给的照片或已通过质检的抽帧中挑选可用图，建立原图与成品的对应。
2. 看照片能说到哪一步。餐盒摞在备餐台上可以写装盒。车、送达地点、取餐对象或交接过程各要有相应素材或用户事实支持。拿不准是不是同一个项目、同一天或同一批餐时，用几张照片并列记录。
3. 根据主题挑封面和翻图顺序。先用一张具体照片建立看点，第二张接住封面，后面再换尺度或补场景。交错使用单图、同角度对照和必要的拼图。保留菜盘份量、台面和通道等能让人看懂的边缘。
4. 图序定了再写。用照片里一个具体细节开头，写出符合授权身份的观察。业务词放在照片来源、现场动作或服务对象自然出现的位置。正文长短由素材和用途决定，写完读一遍，删去采购教程、通用宣传词和无依据的服务承诺。
5. 导出或交付前复核。成品按翻图次序命名，首张即封面。用手机阅读尺度看首图和连续两张，核对文案点到的菜、空间和图序。用户要成稿时给标题、正文、适量话题和对应图片。研究证据和内部素材编号留在发布文案之外。

写真处理以裁切、旋转、轻调和排版为主，保留真实菜品、份量、设备和工作状态。价格、覆盖区域、资质、客户、餐量和操作承诺以用户提供的事实为准。公开输出前处理用户未授权公开的身份信息。原始素材、待发文案和渲染产物留在任务输出目录，例如 `runs/xhs-<job>/`。

## 什么时候查资料

- 写稿、选图或改版时读 [图序和文案](references/editorial-patterns.md) 中对应主题。
- 用户要求做小红书研究，或需要新的案例验证选择时，读 [原帖证据](references/observed-notes.md)。云端有可用的 Agent Reach 或登录浏览器时可做只读站内检索。用户要求实时原帖时应区分搜索摘要、实际正文、看过的轮播页和已加载评论。没有站内访问时直接使用提供的素材和已记录样本，并说明本次证据来源。
